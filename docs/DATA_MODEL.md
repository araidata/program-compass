# Preliminary relational data model

> Governing update: the 2026-11-23 strategic scope correction and latest Framework Alignment requirements below supersede conflicting historical proposals. Dedicated framework assessment and implementation tracking are core; enterprise GRC workflows remain excluded. Current authorization: documentation review only.

The future domain relationships below remain proposals. The implemented secure persistence foundation is described first.

## Implemented foundation

User (fixed admin/editor/viewer role, active flag) has many credential Accounts and revocable Sessions. Verification and RateLimit support Better Auth’s adapter. Email is unique/normalized. Passwords are salted hashes in Account; session tokens are server-managed credentials and never returned by application admin APIs.

Organization and ApplicationSettings are constrained singletons. Organization has three configurable Pillars, each with many OrganizationalFunctions (unique name per pillar). The Architecture and Engineering functions are distinct under the SA&E pillar. ChangeEvent optionally references its actor User and records entity/action/time plus allowlisted JSON details. Foreign keys restrict deletion of referenced configuration/history actors; sessions/accounts cascade on user deletion. There is no tenant model.

UUID string identifiers, createdAt/updatedAt on mutable records, indexes for sessions and chronological history, explicit role enum and migration SQL check constraints. Migration: 202611230001_foundation. No organization metrics/personnel or real assessments seeded.

## Implemented capability slice (2026-11-24, migration 202611240001)

Capability (unique code, catalogue version, display group, applicability, nullable current/target level 1–5, scale version, confidence, rationale, review state, target date, optional accountable OrganizationalFunction, assessor and time) has many CapabilityPillar joins (composite key, no exclusive pillar), many CapabilityIndicator rows (optional unique catalogue key, direction, decimal pass/fail boundaries with an order check, nullable value and measured date, unique name per capability) and many CapabilityRequirementMapping rows. Framework (unique key and version) has hierarchical FrameworkRequirement rows (unique identifier per framework). Mappings use a composite key and never hold maturity. Deleting a referenced framework requirement is restricted; deleting a user sets assessor/updater to null.

## Corrective domain design — strategic scope (proposal, 2026-11-23)

The implemented foundation above is unchanged. This section replaces the ambiguous ComplianceAssessment proposal with explicit organizational RequirementAssessment/ImplementationObservation records and excludes enterprise risk/audit domain interpretations. No schema/migration is changed in this review.

| Domain                               | Proposed data and constraints                                                                                                                                                                                                                                                                                                               | Strategic use                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Capability catalog                   | Stable original topic IDs, catalog version, description/subjects, CSF mappings, applicability and pillar/function joins                                                                                                                                                                                                                     | Assess shared capabilities once                                                                                       |
| Assessment/performance               | Dated capability assessment/scale version; KPI definition, unit, direction, pass/fail thresholds and dated observations; separate targets and reviews                                                                                                                                                                                       | Reproduce current/target gaps and performance deficiencies                                                            |
| Context                              | Profile versions, objective priority/person owner, business threats with objective/capability joins                                                                                                                                                                                                                                         | Explain business consequences/priorities                                                                              |
| Responsibilities/people              | Responsibility/function/pillar joins; Person, Position, assignment, manager, accountable ownership FKs                                                                                                                                                                                                                                      | Ownership and workload basis; Person separate from login User                                                         |
| Framework references and assessments | FrameworkVersion/RequirementReference (official IDs, hierarchy, descriptions, source); separate organization/cycle RequirementAssessment, applicability, ImplementationObservation, current/target scores/scale, notes, observations/history; capability/responsibility/technology/workforce/initiative links, reference URLs and deadlines | Dedicated Framework Alignment and capability/resource drivers; no evidence platform, certification or approval engine |
| Planning issues                      | Lightweight deficiency or external risk/finding reference; source, consequence, simple planning state, owner/date, capability/initiative/resource joins                                                                                                                                                                                     | Justify development/investments; no enterprise register or audit lifecycle                                            |
| Initiatives/plans                    | InitiativeCapability expected uplift, issue/resource links, dependencies, dates, status/approval distinction, Decimal costs/currency; cycle/plan/scenario years                                                                                                                                                                             | Sequence initiatives and avoid treating forecasts as actual maturity                                                  |
| Resource extensions                  | NICE version/roles/tasks, unique WorkActivity and sourced workload/capacity assumptions; TechnologyCoverage/utilization and cost lines                                                                                                                                                                                                      | Staffing justification, technology options and annual forecasts                                                       |

Uniqueness for mapping pairs/activities, no reporting/dependency cycles, explicit unknown vs zero, immutable assessment provenance, optimistic concurrency and transactional authorized writes need schema review. Preserve dated inputs, methodology version, as-of/scope, currency and cost identity. A shared mapping cannot create additional assessments, workload or spend. Keep one plan with detailed years 1–3/directional years 4–5. Separate production from labeled synthetic evaluation data; safe imports need schema-version validation, referential checks, preview and all-or-nothing application. Do not assume browser CSV exports are a full relational backup.
