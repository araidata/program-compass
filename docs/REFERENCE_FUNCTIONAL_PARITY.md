## Deficiencies, retained components and corrective direction

No reference business workflow currently meets functional completion. `/context`, `/capabilities`, `/compliance`, `/risks`, `/roadmap`, `/workforce`, `/technology`, `/reports` are generated placeholders with planned-view text; `/` is an initialization overview. Settings has real configuration/accounts/history functionality, which is useful infrastructure rather than a capability assessment. Prisma contains only User, Account, Session, Verification, RateLimit, Organization, Pillar, OrganizationalFunction, ApplicationSettings, ChangeEvent. Capability assessments, original catalog/KPIs, framework reference and requirement assessment records, person ownership, workload, technology, issues, initiatives and plan/scenario costs are absent.

Retain `app-shell`, `scoped-link`, `scope-switcher`, `use-scope`, `page-header`, tokens/UI primitives; native auth/access/API/administration helpers; Prisma schema/migration tooling, npm lockfile, tests and GitHub/Vercel/Neon integration. No source/infrastructure rewrite is justified. Existing Recharts dependency is not a completed visualization. Modify placeholder route content and future navigation labels, extend server authorization/history to business writes, introduce people-based ownership/URL filters and calculation selectors. Add cards/minimap/rating grid/KPI bands, relational panels, framework hierarchy and coverage heat maps, history/trend/current-target-projected views, timeline, org chart, report/export components. Retain `/compliance` compatibly as Framework Alignment; retire standalone enterprise risk navigation only when approved.

A dedicated Framework Alignment section is required. Removing it or restricting frameworks to static reference links would fail the latest request. Separate versioned official reference content from editable organizational applicability, implementation, maturity, notes and history. Shared capability maturity remains authoritative; requirement-specific facts do not duplicate it. Full compliance certification/evidence/audit/control-testing/exception/continuous-monitoring engines remain excluded. Broad risk scoring/heat maps are optional, not required parity. Lightweight planning issue references retain rationale and links without rebuilding external systems.

The shell can accommodate this domain model through additive modules and migrations. Historical phase sequencing delayed essential relationships/analytics; proposed slices prioritize complete connected capability/context/framework/direction/reporting flows, then resource/multiyear extensions. Future release acceptance must trace context→capability/requirement deficiency→responsibility→position/tool→initiative→annual cost→three/five-year plan→progress. Extensible framework support is core; optional AI and extra enterprise integrations do not precede that workflow.
