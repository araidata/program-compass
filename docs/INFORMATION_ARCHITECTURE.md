# Information architecture — proposal

Preserve existing routes pending Claude Code UI/UX review. Current navigation is provisional; a simpler alternative combines risks into Assessment and people/technology into Resources. Decide before substantive frontend development.

| Route                 | Future contents                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------- |
| /                     | Executive overview, enterprise and pillar filters                                        |
| /business-context     | Organization profile, objectives, business functions, threats, dependencies              |
| /current-state        | Capabilities, responsibilities, maturity, targets, KPIs                                  |
| /compliance           | Frameworks, requirements, applicability, mappings, coverage and separate verified status |
| /people-resources     | Positions, personnel, NICE roles, workload, capacity, staffing proposals                 |
| /technology-portfolio | Inventory, coverage, utilization, costs, renewals and alternatives                       |
| /strategic-planning   | Initiatives, one plan with three/five-year views, scenarios, budget and deferral         |
| /risks-findings       | Lightweight risks/findings linked to capabilities and initiatives                        |
| /reporting            | Executive/management exports with assumptions and calculation traceability               |
| /settings             | Future users, roles, catalogs and assumptions                                            |

Future flow: establish context → assess applicability and capabilities → identify gaps → model workforce and technology options → sequence initiatives against deadlines/dependencies → compare annual funding scenarios → report rationale and remaining risk. Authentication eventually directs immediately to the dashboard.

Use compact tables, filters, sorting, labeled forms, linked record details and progressive disclosure. Keep enterprise/pillar views consistent without duplicating shared capabilities. Distinguish unassessed, current, target, approved, proposed and hypothetical states. Reuse records rather than entering a responsibility separately for every framework. Foundation pages collect no data.
