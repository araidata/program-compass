Proposed grouping: Overview; Assess (Capabilities, Framework Alignment); Plan (Business Context, Roadmap); Resources (Workforce, Technology); Reports; Settings. Existing grouped shell and URL pillar scope remain useful. Do not rename routes or alter navigation during this documentation review. After approval, keep `/compliance` as the Framework Alignment route to preserve links; redirect legacy `/risks` to relevant capability planning issues, preserving valid pillar scope. A future `/framework-alignment` rename is optional and requires an explicit compatibility plan. Current placeholder labels and phase numbers remain historical until that change lands.

The main workflow is context/complexity → applicable capabilities → maturity/performance → targets → deficiencies → responsibilities → workforce workload/capacity → technology gaps → initiatives → investment forecasts → detailed three-year plan/directional five-year outlook → strategic progress. People/owner records are needed before staffing calculations; login Users are separate.

The module layout is a default, not a table-only restriction. Retain useful reference concepts: capability cards, expandable descriptions/subjects, keyboard rating controls, KPI bands, current/target comparisons, timeline, org chart and dense linked tables. Capability details combine assessment, performance, targets, responsibilities, relevant framework requirements/deadlines, staffing/technology links, planning issues and initiatives. Framework Alignment is an analytical assessment workspace, not generic CRUD: NIST function/category maturity, CJIS implementation, coverage heat maps, unmapped requirements, strengths/weaknesses, current/target/gaps, pillar maturity, historical trends and projected future state. It supports requirement-specific assessments, separate from shared capability maturity. Framework coverage never establishes verified compliance. Related-record panels retain context; confirmations alone use modals.

CSF functions, SOF organizational pillars and responsibility ownership are separate dimensions. The reference displays five groups with Respond/Recover combined; authoritative CSF mapping must preserve six functions. Shared capabilities are assessed once, not copied by pillar/framework. URL filters, clear scope/as-of labels and common calculation results connect charts, tables and reports. Provide keyboard paths, labeled status, textual chart equivalents, save/error feedback and responsive reading/overflow. No branding, contact capture or decorative graphics.
